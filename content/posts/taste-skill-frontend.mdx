写前端时，最容易翻车的不是「会不会写组件」，而是**默认审美被模型带跑**：紫色渐变、居中大标题、三列等宽卡片、到处是 `shadow-xl`。看起来像演示，不像产品。

`taste-skill` 这类技能库的价值，不在「多一个 Prompt 模板」，而在把**高级感的约束写成系统规则**：间距、字体、阴影材质、动画强度，甚至强制完整输出、禁止 `// ...省略`。

## 它解决什么问题

和 AI 协作前端，常见三种失败：

1. **布局僵化**：永远左文右图、永远 12 列对称网格。
2. **视觉廉价**：高饱和渐变 + 重阴影 + 无意义玻璃拟态。
3. **代码半截**：只给关键片段，落地时还要自己补全路由、状态和边界。

技能库把这些失败模式**显式禁止**，再按场景叠风格技能——极简、工业粗野、高端 Agency——而不是每次从零描述「我要高级一点」。

## 技能怎么分层

可以粗分成三层，组合使用比单装一个更稳：

### 1. 核心约束（写代码时必挂）

- **`design-taste-frontend`（V2）**：综合约束最强，带可调旋钮（多样性、动效强度、视觉密度）。
- **`gpt-taste`**：更针对 GPT / Codex 容易「千篇一律」的问题，用更强硬的随机化逻辑打破僵局。
- **`full-output-enforcement`**：**建议常驻**。禁止省略号式输出，逼模型给可运行完整代码。
- **`redesign-existing-projects`**：不是新开页面，而是爆改旧站——修间距、层级、组件节奏。

### 2. 视觉风格（定情绪）

- **`minimalist-ui`**：留白、克制、杂志感，适合阅读型博客。
- **`industrial-brutalist-ui`**：硬边、高对比、等宽字与终端隐喻，适合极客主页。
- **`high-end-visual-design`**：大留白、丝滑微动效、衬线/无衬线混排，适合品牌与产品落地页。

### 3. 图像与参考（先图后码）

- **`imagegen-frontend-web` / `mobile`**：生成高完成度 UI 参考图。
- **`image-to-code`**：先出图、再拆图、再落代码的一条龙。
- **`brandkit`**：Logo、情绪板、品牌系统概念。

原则很简单：**风格技能定方向，核心技能定底线，完整输出保证能跑。**

## 三个可抄的场景配方

下面不是魔法咒语，而是「技能组合 + 需求写法」的示例。换成你的栈（Vite / Next / 纯 HTML）同样适用。

### 场景 A：极简个人博客

**组合**：`gpt-taste` 或 `design-taste-frontend` + `minimalist-ui` + `full-output-enforcement`

**提示词骨架：**

> 用 React + Tailwind 做个人博客首页。严格遵循 `minimalist-ui`；完整输出、不截断。  
> 旋钮：`DESIGN_VARIANCE=3`，`MOTION_INTENSITY=3`，`VISUAL_DENSITY=2`。  
> 导航极简；大号无衬线标题 + 短简介；文章列表只有标题 / 日期 / 一行摘要。  
> Hover 只做轻微透明度或 1–2px 位移，禁止彩色大阴影。

### 场景 B：硬核极客主页

**组合**：`gpt-taste` + `industrial-brutalist-ui` + `full-output-enforcement`

**提示词骨架：**

> 工业粗野主义：无圆角、无柔阴影，1–2px 实线框，黑白高对比 + 一种刺眼强调色。  
> 等宽 / 粗无衬线；模块命名像系统面板（状态、部署、核心栈）。  
> 交互偏终端感：闪烁、瞬间切换，拒绝「丝滑营销页」动效。

### 场景 C：高端产品落地页

**组合**：`design-taste-frontend` + `high-end-visual-design` + `full-output-enforcement`

**提示词骨架：**

> 低饱和色、大量留白；Hero 用 Serif + Sans 混排。  
> 产品网格错落，不要死板三列。  
> CTA 尝试线框 / 磨砂 / 磁性 hover，而不是默认实心圆角按钮。  
> `MOTION_INTENSITY` 可以拉高，但每个动效都要有「为什么动」。

## 我实际用的时候会盯这几条

1. **先选风格，再写功能**。功能清单很长、审美未定，模型一定回落到 SaaS 默认皮。
2. **旋钮宁小勿大**。博客首页的 `MOTION_INTENSITY=8` 往往只是吵，不是高级。
3. **改造旧站用 redesign 技能**，不要假装是「从零新建」——上下文不同，约束重点不同。
4. **完整输出是纪律**。半截代码 +「其余类似」= 你自己加班。
5. **对照真实站点校准**。技能防 AI 味，审美仍要靠你自己看过好东西——这点下一篇单独写。

## 小结

Taste-Skill 不是替你审美，而是**缩小模型的合法解空间**：少一点默认紫渐变，多一点可执行的排版与材质约束。

装对技能、写清场景、强制完整输出——前端协作会从「再美化一下」变成「按这套系统交付」。剩下的，是你对密度、留白和节奏的判断。
